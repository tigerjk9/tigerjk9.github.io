웹에서 하는 일은 생각보다 단순한 동작의 반복이다. 슬랙에서 대화를 읽고, 노션에 옮기고, 대시보드에서 숫자를 확인하고, 파일을 내려받는다. AI에게 내용을 물어볼 수는 있었지만 클릭과 입력은 여전히 사람이 맡는 경우가 많았다.

Aside는 이 틈을 겨냥한 AI 에이전트 브라우저다. 웹페이지를 요약하는 데서 멈추지 않고, 로그인된 사이트를 오가며 클릭하고 입력하고 파일을 다룬다. 중요한 차이는 ‘답을 주는 브라우저’보다 ‘브라우저 안의 일을 처리하는 도구’에 가깝다는 점이다.

이 글은 Aside를 처음 설치하는 사람이 첫 작업을 무리 없이 끝내는 데 초점을 맞췄다. 기능을 모두 켜기보다 읽기 전용 작업에서 출발해, 필요한 만큼만 권한과 자동화를 넓혀 간다.

## 시작하기 전에 확인할 세 가지

첫째, 2026년 9월 21일 현재 공식 다운로드 대상은 macOS다. 두 원문은 macOS 15.0 이상을 안내하며 Windows 버전은 준비 중이라고 설명한다. 운영체제 지원은 바뀔 수 있으므로 설치 전 [공식 다운로드 페이지](https://aside.com/download)를 다시 확인하는 편이 좋다.

둘째, Aside는 기본 브라우저를 당장 교체하려는 사람보다 로그인 뒤에 반복되는 웹 작업이 있는 사람에게 더 잘 맞는다. 다음 중 하나가 자주 반복된다면 시험해 볼 만하다.

- 여러 웹페이지를 읽어 한 문서로 정리한다.
- 슬랙이나 이메일 내용을 노션·문서 도구로 옮긴다.
- 대시보드에서 정해진 수치를 확인한다.
- 매주 같은 사이트에서 가격이나 좌석, 공지를 확인한다.
- 로그인해야 보이는 페이지에서 자료를 모은다.

셋째, 처음부터 결제·발송·삭제를 맡기지 않는다. 읽고 요약하거나 임시 문서를 만드는 일부터 시작해야 결과를 확인하기 쉽고, 문제가 생겨도 되돌릴 수 있다.

## 다른 AI 도구와 무엇이 다른가

AI 브라우저라는 이름 아래 서로 다른 도구가 모여 있어 처음에는 구분하기 어렵다. 용도를 기준으로 나누면 간단하다.

| 도구 유형 | 주로 잘하는 일 | 결과가 남는 곳 |
|---|---|---|
| Comet 같은 검색 중심 AI 브라우저 | 검색, 여러 출처 조사, 현재 탭 요약 | 브라우저의 답변과 탭 |
| Claude Code 같은 코딩 에이전트 | 로컬 파일 수정, 코드 실행, 개발 작업 | 파일, 터미널, 저장소 |
| Aside | 로그인된 웹사이트를 오가는 다단계 작업 | 웹서비스, 다운로드 파일, 작업 기록 |

예를 들어 “이 제품에 관한 자료를 찾아 비교해 줘”는 검색 중심 브라우저가 자연스럽다. “이 폴더의 코드를 고쳐 줘”는 코딩 에이전트의 일이다. “슬랙의 이 스레드를 읽고 노션에 결정 사항과 할 일을 정리해 줘”처럼 사이트 사이를 이동해야 하면 Aside의 성격이 드러난다.

이 구분은 우열이 아니라 작업 장소의 차이다. Aside도 긴 글을 쓰거나 깊이 분석할 때는 연결된 AI 모델의 도움을 받는다. Aside가 더하는 것은 그 모델이 브라우저에서 행동할 수 있게 하는 실행 환경이다.

## 10분 안에 첫 작업 준비하기

### 1. 설치하고 복구 정보를 보관한다

[공식 사이트](https://aside.com/)에서 설치 파일을 받아 실행한 뒤 계정을 만든다. 온보딩에서는 계정 비밀번호와 12단어 복구 키를 설정한다. 회사가 비밀번호를 대신 초기화해 주지 못하는 구조라고 안내하므로 복구 키를 잃어버리지 않게 별도로 보관해야 한다.

처음부터 모든 사이트에 로그인할 필요는 없다. 첫 실습에 사용할 사이트 한두 곳만 연결해도 충분하다.

### 2. 기존 브라우저 설정을 가져온다

북마크와 방문 기록을 옮기면 새 브라우저에서 다시 환경을 만드는 수고가 줄어든다. macOS 메뉴에서 `Aside → Aside 정보`로 들어간 뒤 `You and Aside → 북마크 및 설정 가져오기`를 선택한다. Safari는 먼저 `파일 → 내보내기`에서 만든 ZIP 파일이 필요하다.

### 3. 비밀번호 접근 범위를 좁게 시작한다

Aside의 비밀번호 관리자는 자격 증명 원문을 모델에 보여 주지 않고 로그인 화면에 자동으로 채운다고 설명한다. 사이트 단위 접근 제어와 사용 기록도 제공한다.

처음에는 금고가 잠금 해제된 동안만 접근을 허용하는 `While unlocked` 같은 제한적인 정책으로 시작하는 편이 낫다. 자주 쓰는 사이트에 직접 로그인해 정상 작동을 확인한 뒤 범위를 넓힌다.

### 4. 사용할 AI 모델을 연결한다

설정의 `Models`에서 모델 사용 방식을 고른다.

| 연결 방식 | 비용이 청구되는 곳 | 처음 시작할 때 |
|---|---|---|
| Aside 내장 모델 | Aside 크레딧 | 별도 구독이 없을 때 간편하다 |
| ChatGPT·Claude·Copilot 구독 | 기존 구독 | 이미 유료 구독 중이라면 먼저 검토한다 |
| OpenAI·Anthropic·Google·OpenRouter 등의 API 키 | 각 API 계정 | 사용량과 과금을 직접 관리할 때 적합하다 |

두 원문에 따르면 기존 AI 구독을 연결한 작업은 Aside 크레딧을 쓰지 않는다. 서비스 정책과 지원 모델은 바뀔 수 있으므로 실제 연결 화면의 안내를 기준으로 확인한다. API 키를 쓸 때는 개인 키를 공유 문서나 프롬프트에 붙이지 않는다.

### 5. 읽기 전용 지시로 시험한다

첫 작업은 현재 페이지를 읽고 정리하는 수준이 좋다. Ask AI 패널을 열고 다음처럼 입력한다.

```text
지금 보고 있는 페이지를 읽고 핵심 내용을 5개 불릿으로 정리해.
페이지를 수정하거나 버튼을 누르거나 메시지를 보내지 마.
확인할 수 없는 내용은 추측하지 말고 표시해.
```

## Ask AI와 태스크와 루틴 고르기

Aside에는 일을 시키는 입구가 세 가지다. 작업의 길이와 반복 여부로 고르면 된다.

| 기능 | 언제 쓰는가 | 첫 예시 |
|---|---|---|
| Ask AI | 지금 보고 있는 화면에서 끝나는 짧은 일 | 이 페이지를 표로 요약하기 |
| 태스크 | 여러 사이트나 파일을 거치는 한 번의 일 | 슬랙 내용을 읽고 노션 초안 만들기 |
| 루틴 | 정해진 시간에 같은 일을 되풀이할 때 | 매주 월요일 경쟁사 가격 확인하기 |

Ask AI는 macOS에서 `Command+E`로 열 수 있다. 태스크는 별도의 작업 세션과 단계 로그가 생기며, 루틴은 일정을 정해 반복 실행한다. Free 플랜은 활성 루틴을 최대 3개까지 제공하고, 두 원문 기준 Pro부터는 루틴 수 제한이 없다.

기능을 배우는 순서도 이 표와 같다. Ask AI로 현재 화면을 읽는 데 익숙해진 뒤 태스크로 사이트를 두 개 연결하고, 같은 태스크를 몇 차례 안정적으로 끝낸 다음에 루틴으로 옮긴다.

## 성공률을 높이는 지시문 네 칸

브라우저 에이전트에게는 “알아서 해 줘”보다 경계가 분명한 지시가 잘 맞는다. 목표, 대상, 결과 형식, 멈춤 조건을 한 번에 적는다.

```text
목표: 이 슬랙 스레드의 논의를 회의 기록으로 정리해.
대상: 현재 열린 슬랙 스레드와 ‘주간회의’ 노션 데이터베이스만 사용해.
결과: 제목, 결정 사항, 담당자별 다음 행동이 있는 새 초안을 만들어.
멈춤: 노션에 게시하거나 다른 페이지를 수정하기 직전에 멈추고 나에게 확인해.
```

이 형식은 에이전트가 어느 사이트까지 접근해도 되는지, 무엇을 결과로 남겨야 하는지, 어디서 사람을 기다려야 하는지 알려 준다. 처음에는 “초안만 만들기”, “다운로드까지만 하기”, “제출 직전에 멈추기”처럼 종료선을 구체적으로 적는 편이 좋다.

권한도 작업에 맞춰 고른다.

- `Read only`는 읽고 정리하는 작업에 쓴다.
- `Guard`는 민감한 행동 전에 승인을 받는 기본 선택이다.
- `Full access`는 충분히 검증한 낮은 위험의 작업에만 제한적으로 쓴다.

Guard가 켜져 있어도 결과를 맹신해서는 안 된다. Aside 이용약관도 AI 출력과 행동이 틀리거나 불완전할 수 있으며, 메시지·구매·결제·예약·계정 변경·삭제·게시처럼 되돌리기 어려운 행동은 사용자가 검토해야 한다고 명시한다.

## 처음 해보기 좋은 세 가지 작업

첫 주에는 결과를 쉽게 대조할 수 있는 일을 고른다.

### 읽고 요약하기

```text
현재 페이지와 연결된 원문 두 개를 읽고,
공통 주장과 서로 다른 주장을 2열 표로 정리해.
출처 링크를 각 행에 붙이고 웹페이지는 수정하지 마.
```

### 자료 내려받기

```text
이번 달 청구서 페이지에서 PDF 파일을 찾아 Downloads에 저장해.
파일명은 서비스명-2026-09.pdf로 바꾸고,
다운로드 외의 설정 변경이나 결제는 하지 마.
```

### 다른 서비스에 초안 만들기

```text
현재 슬랙 스레드를 읽고 결정 사항과 다음 행동을 정리해.
노션 ‘업무 기록’ 데이터베이스에 새 페이지 초안만 만들고,
완료 버튼이나 외부 공유는 누르지 마.
```

한 번 성공한 지시문은 바로 루틴으로 만들지 않는다. 같은 조건에서 두세 번 실행해 결과 형식과 승인 지점이 안정적인지 확인한다. 사이트 화면이 바뀌면 자동화도 달라질 수 있다.

## 무료로 어디까지 가능한가

두 원문이 확인한 2026년 8월 가격은 Free 0달러, Pro 월 20달러, Max 월 200달러다. Free는 월 500크레딧과 루틴 3개, 비밀번호 관리자, 메모리, 구독 연결을 포함한다. Pro는 사용량 확대, 심층 조사 기능인 Ultrabrowse, 무제한 루틴, Slack·Telegram 원격 제어와 클라우드 핸드오프를 제공한다.

가격과 제공량은 바뀔 수 있다. 처음부터 유료 플랜을 고르기보다 Free에서 기존 AI 구독을 연결하고, 반복 작업이 실제로 시간을 줄이는지 확인한 뒤 결정하는 편이 합리적이다. 크레딧은 작업의 단계 수에 따라 달라질 수 있어 복잡한 태스크의 소모량을 실행 전에 정확히 예측하기 어렵다는 사용 후기도 있다.

한 사용기는 Free 플랜에서 두 가지 실험을 진행했다. Hacker News 상위 기사 세 건을 한국어로 요약하는 작업은 18초, 구글 검색을 거쳐 Aside Pro 가격을 확인하는 작업은 39초가 걸렸다. 두 작업 뒤에는 500크레딧의 96%가 남았다. 이 결과는 당시 환경에서 수행한 소규모 사례이므로 모든 사이트와 작업의 속도를 보장하지는 않는다.

## 로컬 우선이라는 말을 정확히 읽기

Aside는 로컬 우선 설계를 내세운다. 공식 설명에 따르면 작업 기록과 메모리는 로컬에 저장되고, 비밀번호는 에이전트에 노출하지 않은 채 자동 입력된다. 사용자가 볼 수 있는 `MEMORY.md`, `USER.md`, `TAXONOMY.md` 파일로 기억 내용을 확인하고 고칠 수 있다는 점도 특징이다.

그렇다고 모든 정보가 항상 기기 안에만 머무는 것은 아니다. 공식 개인정보처리방침은 계정·결제·동기화·복구·호스팅 모델 같은 기능이 서버 측 서비스를 이용한다고 밝힌다. AI 태스크를 실행하면 프롬프트, 도구 결과, 선택된 브라우저 화면과 스크린샷, 선택한 파일 등이 작업에 필요한 범위에서 모델 제공자에게 전달될 수 있다. 외부 AI 구독이나 API 키를 연결하면 해당 제공자의 약관과 개인정보처리방침도 적용된다.

따라서 ‘로컬 우선’을 ‘인터넷으로 아무 정보도 나가지 않는다’는 뜻으로 읽으면 안 된다. 민감한 업무를 맡기기 전에는 다음을 확인해야 한다.

- 어떤 계정과 사이트에 접근을 허용했는가
- 현재 작업에 선택된 화면과 파일은 무엇인가
- 어느 AI 모델과 계정을 연결했는가
- 승인 없이 실행할 수 있는 행동은 어디까지인가
- 회사나 학교의 보안 정책이 에이전트 사용을 허용하는가

제품이 내세우는 암호화와 로컬 저장 구조는 공식 설명에 근거한 주장이다. 두 원문이 지적하듯 독립적인 외부 보안 감사가 충분히 공개된 단계는 아니므로, 자격 증명과 민감 데이터의 위험은 사용자가 따로 판단해야 한다.

## 아직 주력 브라우저로 바꾸지 않아도 된다

Aside는 Chromium 기반의 신생 브라우저다. 원문 사용기에는 스크린샷 단계 오류가 발생했지만 작업은 끝까지 완료한 사례가 나온다. 커뮤니티에서는 메모리 사용량, 버벅임, 업데이트 뒤의 버그도 거론된다. 현재로서는 크롬이나 사파리를 유지하고 Aside를 자동화 전용 보조 브라우저로 쓰는 접근이 부담이 적다.

에이전트가 작업하는 동안 패널을 닫으면 처음부터 다시 시작할 수 있다. 시간이 긴 태스크는 탭을 복제하거나 다른 창에서 일을 보고, 실행 중인 패널은 그대로 두는 편이 낫다. 캡차나 추가 인증이 나타나면 우회를 지시하지 말고 사람이 직접 통과한 뒤 이어서 실행한다.

벤치마크 숫자도 같은 태도로 읽어야 한다. Aside는 여러 브라우저 에이전트 평가에서 높은 자체 측정 결과를 공개했지만, 회사가 직접 실행하고 LLM으로 채점한 수치다. 제3자의 독립 검증으로 확정된 순위라기보다 제품의 방향과 개발팀의 자신감을 보여 주는 자료로 보는 편이 안전하다.

## 한 달 뒤 남길 것은 루틴보다 기준이다

Aside를 잘 쓰는 방법은 많은 일을 한꺼번에 넘기는 데 있지 않다. 반복되는 웹 업무 하나를 골라 읽기 전용으로 시험하고, 작업 로그를 확인하고, 승인 지점을 정한 뒤 범위를 넓히는 데 있다.

처음에는 Ask AI로 한 페이지를 읽는다. 다음에는 태스크로 두 사이트를 잇는다. 같은 작업이 안정적으로 반복될 때 루틴을 만든다. 이 순서를 지키면 브라우저 에이전트가 어디서 시간을 줄이고 어디서 사람의 판단을 기다려야 하는지 보이기 시작한다.
