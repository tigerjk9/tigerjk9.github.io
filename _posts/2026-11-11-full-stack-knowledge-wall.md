## 바이브 코더가 마주하는 세 가지 벽

Claude Code나 Codex 같은 코딩 에이전트가 발전하면서 산출물의 범위와 완성도는 눈에 띄게 커졌다. 하지만 도구가 발전해도 사용자가 마주하는 한계는 동일하다.

사내에서 업무용 프로그램을 만들고도 조직의 보안 검토를 통과하지 못하는 사례가 대표적이다. 데이터가 어떻게 흘러가는지 개발자 스스로 설명하지 못하기 때문이다. 인터넷에 서비스를 출시하려 해도 기능적 결함이나 보안 이슈를 확신하지 못해 멈춰 선다. 내 컴퓨터에서는 잘 작동하던 프로그램이 다른 환경에서 에러를 일으킬 때 원인을 찾지 못하고 에이전트에만 의존하는 악순환에 빠진다.

| 벽의 유형 | 발생 상황 | 근본 원인 |
|----------|----------|----------|
| 보안 검토 | 사내 ERP나 학생 관리 시스템 도입 시 차단 | 데이터 흐름과 시스템 구조 설명 불가 |
| 출시 불안 | 공개된 인터넷 상에 서비스 론칭 시 오류 우려 | 기능적 무결성과 잠재적 에러에 대한 확신 부족 |
| 환경 오류 | 로컬 환경에서 정상 작동하던 프로그램이 타 환경에서 구동 실패 | 에러 발생 시 원인 추적 능력 부재 |

## 효능감의 곡선과 풀스택 지식의 벽

초기 사용자는 코딩 에이전트가 예상보다 훨씬 많은 양의 산출물을 만들어내기 때문에 자신의 효능감이 급상승하는 경험을 한다. 하지만 프로그램을 고도화하고 실제 론칭 단계로 넘어가면서 난관에 부딪힌다. 자신이 가진 기술적 한계를 인지하는 시점이 오고, 여기서 본격적인 벽을 마주한다.

영상의 강사는 2013년부터 퍼블리셔, 백엔드, 프론트엔드, 데브옵스, AI 개발까지 10년이 넘는 실무 경험을 쌓으며 모든 스택을 직접 체화했다. 고객에게 호통을 들어가며 밤을 새워 익힌 이 실무 지식이 있었기에 바이브코딩 시대에 에이전트를 주도적으로 통제할 수 있었다. 에이전트가 코드를 대신 작성해 준다 해도, 그 코드를 판단하고 운영할 풀스택 지식은 사용자의 몫이다.

## 100시간의 학습 로드맵

풀스택 지식을 쌓기 위해 설계된 커리큘럼은 총 10개 회차로 구성된다. 강의 영상, 핸드북 학습, 실습 과정을 거치며 한 회차당 약 10시간이 소요된다. 강사는 이 100시간을 자신이 10년에 걸쳐 현업에서 익힌 지식을 압축한 과정이라고 소개한다.

| 회차 | 주제 | 핵심 내용 |
|------|------|----------|
| 1회차 | 바이브 코딩의 이해 총론 | 바이브 코딩의 원리, 순서, 방법론 |
| 2회차 | 크롤러 구축과 웹의 이해 | 크롤러 구축을 통한 웹 통신 과정과 브라우저 이해 |
| 3회차 | 플러그인과 CLI 자동화 | SaaS 프로그램과 터미널을 통한 자동화 개념 |
| 4회차 | AWS의 이해와 클라우드 환경 구축 | 배포 환경과 클라우드 내부 작동 원리 파악 |
| 5회차 | JavaScript와 Next.js | 프론트엔드 언어 구조와 소스 코드 독해 |
| 6회차 | Python과 FastAPI | 백엔드 시스템 구축과 데이터 처리 |
| 7회차 | 데이터베이스와 시스템 설계 | 인포메이션 아키텍처와 DB 스키마 설계 |
| 8회차 | Docker와 Kubernetes | 시스템 부하 환경 설계와 리소스 운용 |
| 9회차 | 보안과 고도화 | 제품 생명주기에 따른 보안 및 성능 관리 |
| 10회차 | LLM 에이전트 구축 | 챗봇과 자동화 기능이 포함된 에이전트 설계 |
