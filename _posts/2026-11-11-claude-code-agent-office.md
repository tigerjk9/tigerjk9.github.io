## 하드웨어와 모니터 배치

메인 컴퓨터는 램 64GB, 저장 공간 2TB, Apple M4 Max 칩의 맥 스튜디오다. 원격으로 붙여 쓰는 맥 스튜디오 2대를 더해 모두 3대를 쓴다. 모니터는 상단에 삼성 G9, 하단에 델 모니터 2개다. 원래 하나가 더 있었지만 정신이 없어서 3개로 줄였다.

화면마다 역할이 다르다. 왼쪽 모니터에서 명령을 내리고, 오른쪽에서는 AI가 브라우저로 작업하는 모습을 지켜보고, AI가 만들어 온 결과물은 상단 모니터에 띄워 검수한다. 이렇게 여러 프로젝트를 한 번에 진행한다.

주변기기는 OWC 제품, 오디오 인터페이스 Apollo Twin, 마이크 Shure KSM32, 모니터 상단 조명 BenQ 제품을 쓴다.

## 계정과 월 사용액

Claude Code는 4개에서 16개, Codex는 6개에서 8개 사이를 오간다. 월 사용액은 4,400달러에서 5,000달러, 원화로 1천만 원 가까이다. 여러 계정은 운영자가 직접 만든 팀클로드라는 도구로 묶어 쓰고, Codex 계정도 같은 방식으로 묶는다.

병렬로 많이 돌려도 사용량을 감당하는 방법은 모델을 나누는 것이다. 무거운 판단만 상위 모델에 맡기고 반복 작업은 가벼운 모델로 내린다.

## cmux, Claude Code CLI, ego lite

왼쪽 모니터에서는 Claude Code와 cmux를 쓴다. cmux는 왼쪽에 워크스페이스를 세로 탭으로 나누고, 워크스페이스 안에서 다시 상단 탭별로 작업한다. 어떤 작업을 했는지 탭에 남아 있어서 껐다 켜도 그 세션에서 이어 쓸 수 있다.

Claude Code는 앱이 아니라 CLI로 쓴다. 운영자가 든 이유는 두 가지다. CLI에서 써야 Claude Code의 기능을 온전히 쓸 수 있고, 모든 데이터가 내 컴퓨터로 들어온다.

브라우저는 ego lite를 쓴다. 사용자의 브라우저와 별개로 AI 에이전트 여러 개가 같은 컴퓨터에서 브라우저를 함께 쓰게 해 주는 AI용 브라우저다. 영상 화면에서는 AI가 브라우저 16개를 쓰고 있다.

## 여러 대를 묶는 Tailscale

여러 PC는 Tailscale로 묶는다. 연결한 PC끼리 파일을 주고받을 수 있고, 원격 맥 스튜디오도 이것으로 붙여 쓴다. 영상 편집처럼 CPU와 램을 많이 쓰는 일은 다른 맥 스튜디오에 위임한다.

## 새 맥 스튜디오로 이사하기

영상에서는 2천만 원짜리 맥 스튜디오를 새로 들여 메인 머신으로 삼는다. 이전 작업은 기존 맥 스튜디오의 Claude Code에게 맡겼다. 새 맥 스튜디오로 이전하려 한다고 말하자 Claude Code가 목록을 먼저 작성한 다음 옮기자고 답했고, 그 목록대로 필요한 것만 골라 옮겼다. 디스크를 통째로 복사할 수도 있지만 더미 데이터와 쓰레기 파일이 많아서 분류해 옮기는 쪽을 택했다. 시간은 오래 걸린다.

기존 맥 스튜디오는 워커 머신이 된다. 동영상 렌더링, CI/CD, 검토, 영상 추출 같은 별도 역할을 맡는다. 기존 장비로는 세션을 50개 정도 켜 두면 부족했는데 새 장비에서는 막힘없이 진행된다.

맥 스튜디오는 바닥에 환풍구가 있다. 오래 쓰면 먼지가 많이 끼어 컴퓨터에 무리가 가므로 바닥 먼지를 닦고 청소기로 한 번 밀어 준다.

## 새 맥 세팅 여덟 단계

새 맥을 사면 아래 순서로 세팅한다.

1. 설치 관리자 Homebrew를 제일 먼저 깐다. 나머지 도구를 전부 이것으로 설치한다. 명령어 도구는 `brew install <이름>`, 앱은 `brew install --cask <이름>`, 업데이트는 `brew upgrade`, 삭제는 `brew uninstall`이다. Brewfile이라는 목록에 도구를 적어 두면 `brew bundle`이 한 번에 깔아 주므로 맥을 바꿀 때마다 하나씩 다시 깔 필요가 없다.
2. AI 코딩 도구를 깐다. Claude Code는 터미널에서 대화로 일을 시키는 코딩 에이전트다. 프로젝트 폴더에 `CLAUDE.md`를 만들어 규칙을 적어 두면 매번 읽고 따른다. Codex CLI는 OpenAI가 만든 터미널 코딩 에이전트다. 다른 회사 모델이라 Claude가 놓친 실수를 잡아 주므로, Claude가 만들고 Codex가 따로 검증하게 나눠 쓴다.
3. 터미널을 갖춘다. Ghostty는 GPU로 화면을 그리는 빠르고 가벼운 터미널이고 `brew install --cask ghostty`로 깐다. cmux는 Ghostty를 바탕으로 만든 터미널로, 왼쪽 세로 탭에 세션이 줄지어 보이고 에이전트가 일을 끝내거나 확인을 기다리면 알림을 띄운다. tmux는 터미널 세션을 서버처럼 띄워 두는 도구라 창을 닫거나 접속이 끊겨도 작업이 계속 돈다. 셸에는 Starship(폴더·Git 브랜치·언어 버전 표시), 자동 완성, 문법 강조를 더한다.
4. 개발 기본 도구를 깐다. Git은 변경 기록을 저장해 AI가 고친 것이 마음에 안 들면 이전 상태로 되돌린다. gh는 GitHub를 터미널에서 다루며 AI가 만든 변경을 PR로 올리고 합칠 때 쓴다. Node 버전은 fnm, Python은 uv로 관리한다. 그 밖에 Bun, Docker, jq, ripgrep을 쓴다.
5. 기기를 연결한다. 맥이 여러 대가 되면 필요하다.

   - Tailscale은 기기마다 고정 주소를 주는 개인 네트워크 VPN이다. 공유기나 방화벽 설정 없이 집, 회사, 카페 어디서든 내 맥끼리 연결된다.
   - Mosh는 SSH처럼 원격 맥에 접속하는 도구다. 와이파이를 바꾸거나 노트북을 덮었다 열어도 접속이 끊기지 않는다.
   - Chrome 원격 데스크톱은 다른 맥의 화면을 그대로 보고 마우스로 조작한다.
   - LocalSend는 같은 와이파이의 기기끼리 인터넷 업로드 없이 파일을 보낸다. 윈도우, 안드로이드와도 된다.
6. 영상과 음성 도구를 깐다. FFmpeg는 자르기, 이어 붙이기, 크기 바꾸기, 자막 입히기, 음량 맞추기를 명령 한 줄로 한다. 명령으로 돌아가서 AI가 직접 쓸 수 있다는 점이 중요하다. yt-dlp는 영상과 자막을 내려받고, Whisper는 말을 글로 받아쓴다. OBS는 녹화에, Blender는 화면을 열지 않고 명령만으로 3D 장면을 렌더링하는 데 쓴다.
7. 코딩용 글꼴을 깐다. Nerd Fonts는 터미널 아이콘이 깨지지 않게 해 주고, D2Coding은 한글과 영문 폭이 맞아 줄이 흐트러지지 않는다. D2Coding은 `brew install --cask font-d2coding`으로 깐다.
8. 시스템 설정을 바꾼다. 맥이 중간에 잠들면 AI 작업이 멈춘다. 전원을 연결한 상태 기준으로 네 가지를 바꾼다.
   - 잠자기와 디스크 잠자기를 끈다.
   - 화면만 10분 뒤에 꺼지게 한다. 화면이 꺼져도 작업은 계속 돈다.
   - Wake on LAN을 켠다. 다른 컴퓨터에서 이 맥을 깨워 일을 시킬 수 있다.
   - 정전 뒤 자동 재시작을 켠다. 전기가 나갔다 들어와도 워커가 스스로 다시 켜진다.

   시스템 설정의 에너지 항목에서 바꾸거나 터미널에서 `pmset` 명령으로 바꾼다.

## 시청자 질문에 대한 답

| 질문 | 답 |
|---|---|
| 처음 두 대로 시작한다면 어떤 사양이 좋은가 | 영상 작업은 코어와 램이 모두 많이 필요하다. 비용을 아끼려면 맥 미니 두 대를 연결해 시작한다 |
| 왜 윈도우가 아니라 맥인가 | 에이전트가 돌아가는 데 최적화된 환경이 맥이다 |
| 윈도우 PC로도 계정을 바꿔 가며 이어 쓸 수 있는가 | 가능하다. GitHub에 공유한 팀클로드를 포크해 환경에 맞게 고치면 된다 |
| 맥 스튜디오끼리 일을 나눌 수 있는가 | Tailscale만으로도 분배된다 |
| 그 사용량으로 무슨 작업을 하는가 | 기업에 필요한 에이전트 시스템을 구축한다 |
| 병렬로 많이 돌리면 사용량이 감당되는가 | 무거운 판단만 상위 모델에 맡기고 반복 작업은 가벼운 모델로 내린다 |
