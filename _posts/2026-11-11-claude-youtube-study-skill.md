새로운 것을 배울 때 사람은 유튜브를 검색한다. 유튜브 채널 게으른빌더는 44초짜리 쇼츠에서 이 일을 클로드에게 시키자고 제안한다. 클로드가 튜토리얼 영상을 직접 보고, 거기서 배운 절차를 다음부터 스스로 실행하게 만든다는 것이다. 영상은 설정 세 가지면 된다고 말하고, 구체적인 도구 이름과 순서는 채널이 따로 공개한 가이드 문서에 적어 두었다.

## 영상이 말한 세 가지 설정

쇼츠에서 말로 전한 내용은 다음 세 줄이 전부다.

1. 영상에서 정보를 자동으로 가져오는 스킬을 설치한다.
2. 구글 AI 스튜디오에서 제미나이 API 키를 무료로 받는다. 제미나이가 유튜브를 기본적으로 이해하기 때문이라고 설명한다.
3. 앞의 두 방법으로 얻은 정보를 에이전트 설계 도구에 넣어, 클로드가 그 일을 처리하는 에이전트가 되게 한다.

영상에는 스킬과 도구의 이름이 나오지 않는다. 이름은 고정 댓글에 연결된 가이드 「유튜브 튜토리얼을 클로드가 실행하는 스킬로 바꾸는 세 가지 세팅」에 있다.

## 가이드와 공식 문서에서 확인한 내용

아래 표의 가운데 칸은 채널 가이드가 지목한 도구이고, 오른쪽 칸은 각 도구의 저장소와 공식 문서를 열어 확인한 사실이다.

| 설정 | 가이드가 지목한 도구 | 원 출처에서 확인한 사실 |
|------|----------------------|--------------------------|
| 영상 읽기 | `watch` 스킬 (bradautomates/claude-video) | yt-dlp로 영상을 받고 FFmpeg로 프레임을 뽑아, 시각이 붙은 프레임과 자막을 클로드에게 넘긴다. Claude Code, Codex 같은 스킬 실행 환경에서 동작하고 Claude 채팅 화면이나 Cowork에서는 동작하지 않는다 |
| 두 번째 판독 | 제미나이 API 키와 `google-genai` 패키지 | 제미나이 API는 유튜브 주소를 직접 받는다. 이 기능은 미리보기 단계이고 무료 등급은 하루 8시간 분량까지, 공개 영상만 읽는다 |
| 스킬 제작 | `skill-creator` (anthropics/claude-plugins-official) | 스킬을 새로 만들고, 고치고, 평가 실행으로 시험하는 Anthropic 공식 플러그인이다 |

가이드가 적은 작업 순서는 이렇다. 먼저 클로드가 `watch`로 튜토리얼 영상을 읽고 설명서를 쓴다. 같은 영상을 제미나이에게도 읽힌다. 두 기록을 나란히 놓고 항목마다 확인됨, 한쪽만, 충돌 중 하나를 붙여 설계도 `SPEC.md`를 만든다. 두 기록이 일치하면 확인됨이고, 한 기록에만 있으면 출처를 표시해 남긴다. 충돌한 항목은 평균을 내거나 더 자신 있어 보이는 쪽을 고르지 말고 두 내용을 모두 적은 뒤 그 장면을 다시 보라고 한다. 명령어와 설정값은 글자 그대로 옮긴다. 마지막으로 `skill-creator`가 이 설계도를 스킬로 만들고, 실제 입력으로 한 번 돌려 고친다.

`watch`에는 프레임을 얼마나 뽑을지 정하는 `--detail` 옵션(`transcript`, `efficient`, `balanced`, `token-burner`)과 구간을 자르는 `--start`, `--end`가 있다. 가이드는 기본값 `balanced`를 권하고, 긴 영상을 얇게 훑기보다 짧은 구간을 촘촘히 보는 편이 정확하다고 적었다. 코드나 터미널 화면을 읽어야 하면 `--resolution`을 올린다.

이 방법에서 눈여겨볼 대목은 설치보다 대조 단계다. 영상을 한 번 읽은 AI의 기록에는 잘못 본 화면과 빠뜨린 단계가 섞인다. 서로 다른 방식으로 읽은 두 기록을 맞대어 일치하는 것만 믿는 절차가 있어야 설계도가 쓸 만해진다.

## 적용 장면 1, 도구 튜토리얼을 반복 업무 스킬로

여기부터는 필자의 제안이다. 가장 잘 맞는 장면은 한 번 배워서 여러 번 쓰는 작업이다. 구글 시트 설문 응답을 학급별 탭으로 나누는 앱스 스크립트 튜토리얼처럼, 입력과 결과물이 분명한 10분 안팎의 영상을 고른다.

준비물은 Claude Code, `watch` 스킬과 `skill-creator`, ffmpeg와 yt-dlp, 환경변수로 저장한 제미나이 API 키, 그리고 결과를 시험할 내 자료 한 벌이다.

1. 30초짜리 구간으로 연결을 먼저 확인한다.
2. 영상 전체를 `balanced`로 읽히고 설명서를 쓰게 한다.
3. 같은 주소를 제미나이에게 읽혀 두 번째 설명서를 받는다.
4. 두 설명서를 대조해 `SPEC.md`를 만든다.
5. 충돌 항목은 해당 구간만 `--start`, `--end`로 다시 읽혀 정리한다.
6. `skill-creator`로 스킬을 만들고 내 자료로 한 번 실행해 고친다.

2번과 4번에는 다음 문장을 그대로 쓸 수 있다.

```text
이 영상을 watch 스킬로 balanced 수준에서 읽고, 따라 할 수 있는 설명서를 써 줘.
단계마다 화면에서 누르는 메뉴와 입력하는 코드를 글자 그대로 옮기고,
화면에서 확인하지 못한 내용은 '미확인'이라고 적어 줘.
```

```text
두 설명서를 단계별로 대조해서 SPEC.md를 만들어 줘.
항목마다 확인됨, 한쪽만, 충돌 중 하나를 붙이고,
충돌 항목은 두 내용을 모두 적은 다음 다시 볼 영상 시각을 적어 줘.
```

흔한 실수는 세 가지다. 충돌 항목을 사람이 보지 않고 그럴듯한 쪽으로 넘긴다. 한 시간짜리 영상을 통째로 읽혀 프레임 수만큼 토큰을 쓴다. 영상 속 예시 자료로만 시험하고 내 자료로는 돌려 보지 않는다.

## 적용 장면 2, 연수 영상에서 동료용 안내서 뽑기

스킬까지 만들 필요가 없는 일도 많다. 새 학기에 도입한 도구의 공식 사용법 영상을 동료에게 공유해야 할 때는 `SPEC.md` 단계에서 멈추고 그 문서를 안내서로 다듬는 편이 빠르다. 이때는 `skill-creator`가 필요 없다.

준비물은 Claude Code, `watch` 스킬, 제미나이 API 키, 공개된 사용법 영상 주소다.

1. 영상에서 동료에게 필요한 구간을 정한다. 로그인부터 과제 배부까지처럼 범위를 좁힌다.
2. 그 구간을 클로드와 제미나이에게 각각 읽힌다.
3. 대조표를 만들고 확인됨 항목만으로 안내서 초안을 쓴다.
4. 한쪽만, 충돌 항목은 직접 도구를 열어 눌러 보고 채운다.
5. 영상 주소와 해당 시각을 안내서 끝에 적는다.

```text
확인됨 항목만 써서 처음 쓰는 교사를 위한 한 쪽짜리 안내서를 써 줘.
단계는 번호 목록으로, 메뉴 이름은 화면에 보이는 그대로 적어 줘.
한쪽만, 충돌 항목은 안내서에 넣지 말고 아래에 '직접 확인할 것' 목록으로 따로 모아 줘.
```

여기서 흔한 실수는 영상이 올라온 뒤 도구 화면이 바뀐 것을 모르고 메뉴 이름을 그대로 옮기는 일이다. 4번의 직접 확인을 건너뛰면 안내서를 받은 동료가 첫 화면에서 막힌다.

## 맞지 않는 상황

영상이 약속하는 만큼 되지 않는 경우도 적어 둔다. 쇼츠는 클로드를 각 분야의 전문가로 만든다고 말하지만, 이 방법이 옮기는 것은 영상에 나온 절차다. 화면 조작과 명령어가 순서대로 나오는 튜토리얼에는 잘 맞고, 판단과 경험을 말로 풀어내는 강연에는 맞지 않는다. 그런 영상은 자막만 읽혀 요약하는 쪽이 싸고 정확하다.

제미나이의 유튜브 읽기는 공개 영상만 받는다. 비공개나 일부 공개로 올린 수업 영상은 넘길 수 없다. `watch`는 내 컴퓨터의 영상 파일도 읽지만, 제미나이 엔진을 쓰면 영상이 구글로 올라간다고 README가 밝히고 있다. 학생 얼굴이나 이름이 담긴 영상에는 쓰지 않는 편이 안전하다.

비용도 0은 아니다. 제미나이의 유튜브 주소 기능은 미리보기 기간에 무료이지만 요금과 한도가 바뀔 수 있다고 문서에 적혀 있고, 클로드가 읽는 프레임은 장수만큼 토큰이 든다. 만든 스킬은 튜토리얼이 올라온 시점의 화면과 버전을 따르므로 도구가 바뀌면 다시 확인해야 한다. 남의 유료 강의를 통째로 스킬로 옮겨 배포하는 일은 저작권 문제가 생길 수 있는데, 가이드는 이 부분을 다루지 않는다.
