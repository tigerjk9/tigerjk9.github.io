## 프롬프트 감사 도구의 등장

앤트로픽의 **Lance Martin**은 **클로드 Opus 5.5**를 위해 `/claude-api prompt-audit` 명령어를 사용할 것을 권장했다. 이 명령어는 개발자의 **스킬(skills)**, `CLAUDE.md` 파일, 그리고 일반 **프롬프트**를 검사한다. 특히 최신 모델의 성능을 저해하는 비효율적인 패턴을 찾아내고, 더 이상 필요 없는 지시를 제거하며, **Opus 5.5**에 맞게 프롬프트를 재구성하는 역할을 한다.

이 기능은 **클로드 코드** v2.1.221 버전부터 포함된 기존 도구이나, **Opus 5.5**의 등장과 함께 그 중요성이 다시 부각되었다. 이는 최신 대규모 언어 모델일수록 불필요한 지시를 덜어내고 컨텍스트를 간결하게 정리하는 것이 프롬프트를 계속 덧붙이는 것보다 더 중요해졌음을 시사한다.

## 명령어 작동 방식

`/claude-api prompt-audit`는 **클로드 코드**에 포함된 `claude-api` 스킬의 서브 명령어이다. 이 명령어를 실행하면, **클로드**는 내부 가이드(`shared/prompt-audit.md`)를 바탕으로 다음 작업을 진행한다.

1.  모델에 텍스트로 전달되는 모든 요소(예: `CLAUDE.md`, `SKILL.md`, 규칙 파일, 도구 설명, API 호출 코드)를 파악한다.
2.  `git` 기록이 있다면 `git blame` 명령을 실행해 각 강조된 지시가 언제, 왜 추가되었는지 확인한다.
3.  모든 지시에 대해 "모델이 이미 이 내용을 알고 있는가?" 질문을 던진다.
4.  각 문제점(파일:라인, 정확한 텍스트, 패턴, 구형인 이유, 신뢰도)과 제안된 변경사항을 포함하는 **차이점(diff)** 보고서를 제공한다.

이 도구는 사용자의 명시적인 요청이 있어야만 파일을 수정하며, 사용자 동의 없이 자동으로 변경사항을 적용하지 않는다. 이는 제안된 변경사항을 신중하게 검토하고 선택적으로 적용할 기회를 제공한다.

## 구형 모델용 프롬프트 패턴과 새 모델

`prompt-audit`는 구형 모델을 대상으로 작성된 특정 지시 패턴들이 최신 모델인 **Opus 5.5**에서 오히려 방해가 되는 요소를 찾아낸다. 다음은 이 도구가 주로 지적하는 패턴과 그에 대한 제안이다.

| 기존 프롬프트 패턴               | 제안하는 프롬프트             | 문제점 (모델 관점)                                                                                                   |
| :------------------------------- | :---------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| `CRITICAL: YOU MUST ALWAYS...`, `IMPORTANT!!!` | 정상적인 어조의 규칙과 이유  | 모델이 지시를 너무 문자 그대로 따르는 경향이 있다. 모든 것을 중요하게 취급하면 실제 중요도가 희석된다.            |
| "Think step by step", `<scratchpad>`, `<thinking>` | 해당 지시 삭제                | **Opus 5.5**는 항상 생각하는 과정을 거친다. `effort` 매개변수만이 추론의 깊이를 제어한다.                            |
| "Be thorough. Don't stop early." | 해당 지시 삭제                | 최신 모델은 기본적으로 이미 철저하고 충분히 작업한다.                                                               |
| 판단을 위한 숫자 단계 지정       | 목표와 확인 방법을 설명       | 모델이 번호가 매겨진 단계를 기계적으로 따르기보다, 목표를 이해하고 스스로 판단하도록 유도한다.                    |
| 단일 샘플 답변                   | 삭제 또는 여러 예시 답변 제공 | 단일 예시는 모델을 제한한다. 여러 예시를 제공하거나 아예 없애는 것이 모델의 유연성을 높인다.                         |
| 서로 모순되는 두 가지 규칙       | 하나의 규칙으로 재작성        | 모순된 지시는 모델의 혼란을 유발하고 예측 불가능한 결과를 초래한다.                                               |

특히 **Opus 5.5**의 경우, 모델의 사고 과정 자체는 `effort` 매개변수로만 제어된다. 따라서 "더 생각하라"는 지시는 의미가 없어진다. 또한, 답변에 추론 과정을 포함하라는 지시(reasoning extraction)는 때때로 모델의 거부(refusal)를 유발할 수 있다.

## 감사에서 제외하는 요소

`prompt-audit`는 단순히 프롬프트를 짧게 만드는 도구가 아니다. 특정 패턴과 일치하더라도 모델에 필수적인 내용은 건드리지 않는다.

*   **컨텍스트**: 제품, 환경, 규칙의 배경 등 모델이 다른 곳에서 얻을 수 없는 고유한 정보는 유지한다.
*   **위험한 작업의 정확한 단계**: 파괴적인 명령, 배포, 인증 흐름 등 실수가 치명적일 수 있는 작업에 대한 지시는 그대로 둔다.
*   **여전히 유효한 금지 규칙**: 현재 모델에서도 실패가 반복되는 경우, 해당 금지 규칙은 유지한다.
*   **깔끔한 파일**: 변경할 부분이 없으면 아무것도 건드리지 않는다.

## 실제 사용 결과

**Opus 5.5**를 이용해 세 차례 감사를 진행한 결과는 다음과 같다.

| 감사 항목                                          | 발견된 문제점 수 | 제안된 변경사항 수 | 소요 시간     | 비용      |
| :------------------------------------------------- | :--------------- | :----------------- | :------------ | :-------- |
| 테스트 프로젝트 (`CLAUDE.md`, 안 좋은 습관 스킬)   | 8                | 7                  | 2분 14초      | $2.11     |
| 개인 스킬 저장소 (14개 `SKILL.md` 파일 및 참조) | 16               | 11                 | 5분 39초      | $5.10     |
| 전역 `~/.claude/CLAUDE.md`                         | 5                | 4                  | 2분 22초      | $1.28     |

테스트 프로젝트에서는 "답변을 3줄 이내로 유지하라"와 "모든 변경사항을 자세히 설명하라"는 모순된 규칙 등 의도적으로 심어놓은 모든 문제점을 감지했다. 또한 "묻지 않고 테스트를 실행하지 마라"는 명확한 이유가 있는 규칙은 건드리지 않았다.

개인 스킬 저장소에서는 "think step by step"이나 과도한 대문자 사용 같은 스타일 관련 문제는 사라졌다. 가장 중요한 발견은 스타일이 아니라 더 이상 존재하지 않는 유효성 검사 경로와 같은 **오류**였다.

전역 파일 감사에서는 가장 엄격한 규칙(예: 내 승인 없이 커밋 금지)을 산문 형식에서 `settings.json`의 `ask` 권한 규칙으로 옮길 것을 제안했다.

## 도구 활용 지침

`/claude-api prompt-audit`를 효과적으로 사용하는 방법은 다음과 같다.

1.  **프로젝트 루트에서 실행한다.**
    `cd /your/project/root`
    `/claude-api prompt-audit`
    인수 없이 실행하면 현재 작업 디렉토리 전체를 감사한다. `~/.claude/CLAUDE.md`는 포함되지 않는다.
2.  **특정 파일 지정한다.**
    `/claude-api prompt-audit ~/.claude/CLAUDE.md`
    경로를 지정하면 해당 파일만 감사 범위에 포함한다.
3.  **보고서를 먼저 읽는다.**
    가장 먼저 감사 대상 모델과 파일 범위 등 기본 가정을 파악한다. 발견된 문제점은 신뢰도에 따라 정렬된다. 신뢰도가 낮은 항목은 보고서에만 나타나고 제안된 변경사항 목록(diff)에는 포함되지 않는다.
4.  **확신하는 부분만 적용한다.**
    변경사항은 별도의 파일이나 보고서 내에 차이점(diff)으로 제공된다. 사용자는 변경사항을 적용할지 선택한다. 이 도구는 변경사항 적용 후 결과를 테스트하지 않는다. 따라서 변경 전후를 직접 확인하는 것이 좋다.

## 적용 시기와 기타 도구

모델을 전환할 때마다 이 도구를 실행하는 것이 좋다. 프롬프트는 특정 모델에 맞춰 작성되기 때문에, 한 세대 모델에서 유효했던 지시가 다음 세대에서는 무의미하거나 오히려 방해가 될 수 있기 때문이다.

이 도구는 `/doctor` 명령어와 혼동하지 않는다. `/doctor`는 `CLAUDE.md`의 비대화나 **클로드**가 코드에서 추론할 수 있는 내용을 찾아낸다. 반면 `prompt-audit`는 더 이상 사용하지 않는 구형 모델을 위해 작성된 지시를 찾아낸다.
