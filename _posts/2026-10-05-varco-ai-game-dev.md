게임 하나가 나오려면 기획, 에셋 제작, 프로토타입 개발, QA, 출시 판정을 거쳐야 하고 단계마다 맡는 사람이 다르다. 개발자 revfactory가 깃허브에 공개한 VARCO 게임 스튜디오(varco-platform 저장소)는 이 과정을 클로드 코드(Claude Code) 에이전트 15명에게 나눠 맡긴다. 효과음·대사 음성·3D 모델 같은 에셋은 NC AI가 운영하는 VARCO API 플랫폼으로 만든다. 저장소에는 하네스 말고도 VARCO API 레퍼런스 매뉴얼(PDF)과 소개 영상 세 편이 함께 들어 있다. NC AI가 운영하는 공식 저장소는 아니다.

## VARCO API 플랫폼

VARCO API 플랫폼은 NC AI가 운영하는 AI API 서비스다. 한 번 연동하면 텍스트, 이미지, 오디오, 3D를 다루는 기능을 같은 방식으로 호출할 수 있고, 호출 내역과 크레딧 사용량은 워크스페이스에서 함께 관리한다.

| 분류 | 서비스 | 주요 기능 |
| :--- | :--- | :--- |
| 게임 AI | Sound | 텍스트로 효과음·환경음 생성, 변형, 끊김 없는 루프, 모노→스테레오, 사람 목소리를 몬스터 음색으로 변환, 잡음 제거 |
| 게임 AI | 3D | 이미지 한 장으로 3D 메시와 텍스처 생성(GLB 형식) |
| 게임 AI | SyncFace | 음성으로 입 모양·표정 블렌드셰이프 애니메이션 생성(Voice-to-Face) |
| 미디어 AI | Voice | 빠른 TTS(Lite), 감정 연기 TTS(Standard), 목소리만 바꾸는 음성 변환(Voice Conversion, Acting) |
| 미디어 AI | Translate | 용어집을 반영한 게임 채팅·콘텐츠 번역(10개 언어) |
| 비주얼 AI | Art Fashion | 배경 합성, 시점 변경, 업스케일, 지우기, 인페인트, 텍스처·그래픽 합성, 가상 착장, 헤드스왑 |
| 콘텐츠 비즈니스 AI | Chatbot | FAQ·RAG 기반 상담 챗봇과 지식 관리 |
| 콘텐츠 보호 AI | Gentle Words | 채팅·게시글의 스팸과 금칙어 필터링 |
| 연동 | 플러그인 | VARCO Sound 유니티 플러그인(효과음·루프·크리처·음악·음성을 에디터 안에서 생성) |

시작 순서는 다섯 단계다. 구글 계정으로 가입하면 개인 워크스페이스가 생기고, 여럿이 쓰려면 공용 워크스페이스를 만들어 멤버를 초대한다. 사이드바에서 API 키를 발급하고, 워크스페이스 오너가 크레딧을 구매한 뒤, 요청 헤더에 `OPENAPI_KEY`를 넣어 호출한다. 과금은 사용량 기반 크레딧 방식인데 공식 가격표는 2026년 9월 기준 "공개 예정" 상태다. 키는 코드나 문서에 적지 말고, 유출이 의심되면 바로 폐기하고 새로 발급하라고 README는 안내한다.

저장소에 함께 실린 레퍼런스 매뉴얼은 141쪽 분량의 한국어 PDF다(2026년 9월 28일 기준, 11MB). 제1부 도큐먼트 25편과 제2부 API 레퍼런스 28편으로 나뉘고 이미지 77장과 오디오 샘플 16개가 들어 있다. api.varco.ai에 공개된 문서를 모은 참고용 사본이라 NC AI가 발행한 공식 문서는 아니며, 최신 명세는 공식 API 레퍼런스 페이지에서 확인해야 한다.

## 다섯 단계와 실행 방식

하네스는 에이전트 15명과 스킬 17개로 이뤄진다. 게임 아이디어 한 줄을 받으면 기획 문서, VARCO로 만든 효과음·대사 음성·얼굴 애니메이션·3D 모델·번역 문자열, 플레이할 수 있는 웹 또는 유니티(Unity) 프로토타입, QA 보고서, 출시 판정서를 내놓는다.

단계마다 일의 성격이 달라 실행 방식도 다르게 골랐다.

| 단계 | 실행 방식 | 고른 이유 |
| :--- | :--- | :--- |
| 01 기획 | 이름 붙인 에이전트들이 메시지를 주고받는 지속형 협업 | 시스템·시나리오·레벨·UI 문서가 서로 맞물려 여러 번 조율해야 한다 |
| 02 에셋 명세 | 서브에이전트 한 명 + 사용자 승인 | 매니페스트 한 벌이면 충분하고, 돈이 드는 단계라 사람이 승인해야 한다 |
| 03 에셋 제작 | 워크플로(Workflow) 스크립트 | 만들 에셋 목록과 검증·재작업 규칙을 코드로 정할 수 있다 |
| 04 개발 | 엔지니어와 QA 한 쌍 | 모듈을 끝낼 때마다 바로 검사하고 버그를 주고받는다 |
| 05 출시 준비 | 검사 네 가지를 병렬로 돌린 뒤 디렉터가 판정 | 서로 독립인 검사를 동시에 돌리고, 판정은 한 사람이 기준표로 내린다 |

### 팀 구성

모델은 에이전트의 위상이 아니라 업무 성격으로 골랐다. 막연한 아이디어를 구체화하고 전체를 통합하는 일에는 fable, 설계·코드·교차 검증에는 opus, 절차가 정해진 제작과 검사에는 sonnet을 쓴다.

| 단계 | 에이전트 | 모델 | 하는 일 |
| :--- | :--- | :--- | :--- |
| 기획 | `game-director` | fable | 컨셉 구체화, 기획 문서 통합 리뷰, GDD, 출시 판정 |
| 기획 | `systems-designer` | opus | 코어 루프·시스템 규칙, 밸런스 CSV와 스키마 |
| 기획 | `narrative-designer` | opus | 세계관, 캐릭터, 대사 스크립트, 용어집 |
| 기획 | `level-designer` | opus | 레벨 배치와 난이도 흐름, 사운드 구역, 필요한 프랍 |
| 기획 | `ux-designer` | sonnet | 화면 흐름, HUD, UI 문자열 |
| 기획·출시 | `balance-analyst` | opus | 몬테카를로 시뮬레이션으로 수치 검증, 구현 수치 대조 |
| 명세 | `asset-producer` | sonnet | 에셋 매니페스트, VARCO API 호출 순서, 크레딧 견적 |
| 제작 | `sound-designer` | sonnet | 효과음, 환경음 루프, 크리처 음성 |
| 제작 | `voice-director` | sonnet | 화자 캐스팅, 대사 음성, 얼굴 애니메이션 |
| 제작 | `visual-artist` | sonnet | 3D 모델, 이미지 편집 |
| 제작 | `localization-specialist` | sonnet | 대사·UI 번역, 용어집·자리표시자 보호 |
| 제작·출시 | `asset-qa` | sonnet | 에셋 측정·검증, 출시 전 전수 감사 |
| 개발 | `gameplay-engineer` | opus | 웹(Phaser 3·three.js) 또는 Unity 6 프로토타입 |
| 개발·출시 | `game-qa` | opus | 테스트 계획, 모듈별 검사, 버그 리포트, 회귀 테스트 |
| 출시 | `marketing-artist` | sonnet | 스토어 키 아트·캡슐 이미지, 스토어 설명 |

에이전트끼리 주고받는 파일의 위치와 형식은 산출물 계약서(`contracts.md`) 한 곳에서 정한다.

### 크레딧을 지키는 장치

에셋 생성에는 실제 돈이 들기 때문에 하네스는 크레딧 쪽에 안전장치를 여럿 걸어 두었다.

- 크레딧 승인: 에셋을 만들기 전에 견적을 보여 주고 반드시 사용자 승인을 받는다.
- 예산 차단: 모든 VARCO 호출은 공용 클라이언트를 거친다. 승인한 예산을 넘는 호출은 보내지 않고, 여러 에이전트가 동시에 호출해도 잠금으로 크레딧을 먼저 예약하므로 예산을 넘지 않는다.
- 호출 장부: 드라이런을 포함한 모든 호출이 `varco_ledger.jsonl`에 한 줄씩 남는다.
- 드라이런: 키가 없거나 실제 호출을 원하지 않으면 요청 명세와 견적만 만든다.
- 즉시 중단: 인증 실패나 크레딧 부족이 한 번이라도 나오면 아직 시작하지 않은 에셋은 호출하지 않는다.
- 단가 미공개 API: 번역, Voice-to-Face, 음성 변환 Acting은 단가가 공개되지 않아 따로 승인받아야 호출한다. 승인하지 않으면 연기 변환은 일반 TTS로 대체하고 얼굴 애니메이션은 뺀다.

## 사용 방법

클로드 코드, 파이썬 3(3.10 이상 권장)과 `numpy`·`Pillow`·`requests`, `ffmpeg`·`ffprobe`가 필요하다. 선택 사항은 셋이다. VARCO `OPENAPI_KEY`가 있으면 에셋을 실제로 만들고 없으면 드라이런으로 진행한다. 유니티 프로토타입을 원하면 Unity 6가 필요하며 기본값은 웹이다. Playwright MCP가 있으면 웹 프로토타입을 브라우저로 직접 플레이하며 QA한다.

저장소를 클론하고 의존성을 설치한 뒤 클로드 코드를 실행해 만들고 싶은 게임을 말하면 `varco-game-studio` 스킬이 불린다. README의 예시는 이렇다.

- `무너지는 금고에서 코인을 모아 탈출하는 2분짜리 웹게임 만들어줘`
- `Unity로 VARCO 사운드가 들어간 탑다운 슈터 프로토타입 만들어줘. 번역은 영어와 일본어.`

진행 중에 두 번 멈춰서 묻는다.

1. 컨셉 승인: 디렉터가 쓴 컨셉의 핵심 결정 세 가지를 보여 주고 방향을 확인한다.
2. 크레딧 승인: 에셋 목록과 견적(우선순위별 합계, 단가 미공개 호출 수, 수동 제작 에셋)을 보여 주고 전체 승인, P0만 승인, 드라이런 가운데 고르게 한다.

확정본은 `games/{slug}/`에, 초안·에이전트 간 산출물·크레딧 장부 같은 작업 기록은 `_workspace/{slug}/`에 쌓인다.

이미 진행한 게임은 필요한 부분만 다시 돌린다.

| 요청 | 다시 돌리는 범위 |
| :--- | :--- |
| "밸런스 수정해줘, 적이 너무 세" | 시스템 기획·밸런스 분석 → 데이터 재반영 → 구현 수치 대조 |
| "대사 음성만 다시 뽑아줘" | 3단계를 해당 에셋만 |
| "일본어 현지화 추가해줘" | 에셋 명세에 현지화 추가 → 크레딧 승인 → 3단계 |
| "드라이런 말고 실제로 생성해줘" | 키 확인 → 크레딧 승인 → 3단계 전체 |
| "버그 고쳐줘", "QA 다시 돌려줘" | 4단계 엔지니어·QA 한 쌍 |
| "스토어 이미지 다시 만들어줘" | 마케팅 아티스트만 |
| "출시 판정 다시" | 5단계 |

게임 전체가 아니라 VARCO API를 한두 번만 쓰고 싶다면 공용 클라이언트(`varco_client.py`)를 바로 써도 된다. API 목록과 추정 단가 확인, 호출 전 파라미터 검사, 드라이런, 예산 한도를 건 실제 호출, 장부 요약을 명령 하나씩으로 할 수 있다.

## 알아 둘 점

크레딧 단가는 추정치다. 공식 가격표가 없어서 각 문서에 주석으로 숨겨진 가격표에서 단가를 가져왔다. 번역, Voice-to-Face, 음성 변환 Acting은 단가를 몰라 견적 합계에 들어가지 않는다.

VARCO에 없는 기능도 있다. 텍스트로 이미지를 만드는 API와 음악을 만드는 REST API가 없다. 그래서 3D 모델의 원본 이미지는 사용자가 주거나 다른 이미지 생성 도구로 만들고, 배경음악은 유니티 플러그인에서 사람이 만드는 수동 에셋으로 분류한다.

실제 VARCO 서버로 전체 흐름을 돌려 보지는 않았다. 공용 클라이언트는 로컬 모의 서버로 호출 경로(응답 저장, 3D 결과 조회, 오류 분류, 동시 호출 예산)를 검증했고, 에이전트는 드라이런으로 시험했다. 처음 실제 키로 실행할 때는 결과를 함께 확인해야 한다. 유니티 WebGL 빌드가 필요하면 Unity Hub에서 WebGL 빌드 모듈을 설치해야 한다.

## 쇼릴은 코드로 그렸다

README 맨 위의 1분 쇼릴은 하네스를 시험하며 실제로 만든 게임 "코인 러너"의 대사와 데이터를 소재로 삼았다. 1920×1080, 60fps, 48kHz 스테레오 사양이다. 화면은 HTML 캔버스 한 장에 모든 요소를 코드로 그렸다. 장면마다 시간만 받아 그리는 순수 함수라 어느 프레임이든 똑같이 다시 그릴 수 있다. 소리는 120 BPM, A단조 음악과 효과음 27종을 numpy로 합성했고, 화면과 소리가 같은 큐 시트(`timeline.json`)를 읽어 한 박자 안에서 맞물린다.

같은 엔진으로 만든 2분 제작 과정 영상은 준비부터 출시 판정까지 단계 안에서 일이 넘어가는 순서를 따라간다. 화면 아래 자막 30줄이 장면마다 누가 무엇을 하는지 설명하고, 음악은 장면별 악기 편성을 `timeline.json`에서 읽어 장면 길이를 바꾸면 새 시간표를 따라간다.

매뉴얼과 API 참조 문서 원문의 저작권은 NC AI에 있고, 영상과 매뉴얼에 쓴 Pretendard 글꼴은 SIL Open Font License를 따른다.
