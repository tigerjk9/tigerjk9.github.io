# /naver — 깃허브 블로그 포스트를 네이버 블로그로 크로스포스팅

## 사용법
/naver [옵션]

## 설명
`_posts/`의 포스트를 네이버 블로그(blog.naver.com/dot_connector)에 자동 발행합니다.
Playwright가 로그인된 브라우저(스크립트 전용 프로필)로 스마트에디터 ONE을 조작합니다.
카테고리는 3곳(인공지능교육 인사이트 26 / 뇌기반 학습 과학 84 / 생각하는 교실, 깊이있는 학습 87)
중 Gemini 일괄 분류 결과(`scripts/naver_category_overrides.json`)를 따르고,
본문은 마루부리 15(소제목 19)로 발행됩니다. 글 끝에 원 작성일 + 원문 링크가 자동 삽입됩니다.

## 실행

기본(미게시 포스트 10편 발행, 글 간 45~90초 대기 → 실행당 약 11분):

```bash
py -u scripts/naver_crosspost.py --limit 10
```

`$ARGUMENTS`가 있으면 그대로 전달하세요. 주요 옵션:
- `--dry-run` — 대상 목록·분류 미리보기 (브라우저 안 뜸)
- `--post _posts/파일.md` — 특정 포스트만 발행 (게시 이력 무시하고 재발행)
- `--category ai|brain|class` — 분류 수동 지정
- `--limit N` — 이번 실행 발행 수 (기본 10)
- `--daily-cap N` — 최근 24시간 발행 상한 (기본 20, `0`이면 해제)
- `--min-wait`/`--max-wait` — 글 간 대기 초 (기본 45~90)
- `--no-images` — 이미지 제외
- `--no-publish` — 발행 직전까지만 진행 (검수용, 브라우저 창을 닫으면 종료)
- `--login` — 로그인 쿠키 갱신 (세션이 아직 유효하면 백업만 갱신하고 종료)
- `--force-login` — 유효해도 다시 로그인해 **만료일을 30일 뒤로 초기화** (만료 임박 시)
- `--check-session` — 세션 유효성만 확인하고 종료 (유효 0 / 만료 2, 발행 안 함)
- `--no-auto-login` — 세션 만료 시 로그인 창을 띄우지 않고 즉시 종료 (스케줄러 전용)
- `--classify-gemini` — 신규 포스트 추가 후 분류 갱신 (기존 수동 교정은 보존)
- `--update <logNo> --post <파일>` — 이미 발행된 네이버 글의 본문만 교체
  (제목·카테고리·태그 유지. 변환 로직 개선 후 기존 글 재포맷에 사용)

## 실행 후 반드시

1. 출력의 `[OK] <URL>` 라인으로 발행 성공 여부 확인. `[FAIL]`이면 `scripts/.naver_shots/`의
   에러 스크린샷을 확인하고 원인(팝업 변화, 로그인 만료 등)을 파악할 것
2. 첫 글 URL을 열어 서체(마루부리 15)·표·이미지 렌더링 확인 (모바일 API로 확인 가능:
   `curl -sk https://m.blog.naver.com/dot_connector/<logNo>` 에서 `se-ff-nanummaruburi`·`se-fs-fs15` 클래스)
3. `scripts/naver_crosspost_state.json` 변경분 커밋 (게시 이력 = 중복 발행 방지 데이터)

## 발행 속도 정책 (2026-07-26 상향)
- **실행당 10편 / 글 간 45~90초 / 하루 상한 20편**. 스케줄 2회(10:00·16:00) 기준 하루 20편,
  실행 1회당 약 11분 (이전: 5편·하루 10편. 간격은 2026-07-22부터 쓰던 값 그대로 유지)
- 참고: 네이버는 하루 총량보다 **짧은 시간에 몰아쓰기**를 스팸/저품질 신호로 본다.
  하루 개수에 공식 상한은 없고 상위 인플루언서도 하루 10편대를 쓴다. 간격을 넓히는 게
  더 안전하긴 하나(3~6분안 검토했음), 실행 시간이 45분으로 늘어 운영이 불편해 기존
  45~90초를 유지하기로 결정. 필요하면 `--min-wait 180 --max-wait 360`으로 즉시 전환 가능
- `--daily-cap`은 수동 실행과 스케줄 실행이 겹쳐 과발행되는 사고를 막는 안전판이다.
  상한에 걸리면 그 실행은 조용히 건너뛴다 (`--post` 단건 지정은 예외)
- **첫 1~2주는 관찰 필수**: 새 글이 네이버 검색에 노출되는지, 유입이 급감하지 않는지 확인.
  이상 징후가 보이면 간격을 넓히거나 `--limit 5` + `--daily-cap 10`으로 되돌릴 것

## 운영 규칙
- **자동 실행 등록됨 (2026-07-23부터, 2026-07-26 10편으로 상향)**: Windows 작업 스케줄러
  `NaverCrosspost` 태스크가 매일 10:00·16:00에 10편씩 자동 발행
  (하루 20편, 로그 `scripts/naver_task.log`).
  PC가 꺼져 있으면 다음 부팅 시 실행(StartWhenAvailable). 수동 `/naver` 실행과 겹치면
  프로필 잠금으로 한쪽이 실패하니 스케줄 시간대는 피할 것
  - 시간 변경: `Set-ScheduledTask -TaskName NaverCrosspost -Trigger (New-ScheduledTaskTrigger -Daily -At HH:MM), ...`
  - 중지: `Disable-ScheduledTask -TaskName NaverCrosspost` / 재개: `Enable-ScheduledTask`
- 첫 며칠은 새 글이 네이버 검색에 노출되는지 확인 (검색 누락이 보이면 하루 5편으로 감속)
- **로그인이 풀렸을 때 (2026-07-26 개선)**: 수동 실행(`/naver`)은 세션 만료를 감지하면
  **그 자리에서 로그인 창을 띄우고, 로그인 완료 후 곧바로 발행을 이어간다.** 브라우저에서
  로그인만 하면 되고 별도 재실행이 필요 없다. 창을 직접 닫으면 실패로 끝나니 두고 볼 것.
  스케줄러 실행은 `--no-auto-login`이라 기존대로 `[EXPIRED]` + 종료코드 2로 끝난다.
  쿠키는 `scripts/.naver_profile/cookies.json`에 백업됨 (gitignore, 절대 커밋 금지)
- 네이버 게시일은 실행일이 됨 (원 작성일은 글 말미 표기)
- 새 포스트가 늘면: 자동으로 대상에 포함됨. 분류가 필요하면 `--classify-gemini` 재실행
  (규칙 폴백이 있어 안 돌려도 발행은 됨)
- 분류를 고치고 싶으면 `scripts/naver_category_overrides.json`에서 해당 파일명의 값을
  `ai`/`brain`/`class`로 수정 (Gemini 재실행에도 수동값 우선)

## 브라우저 경고 배너 (2026-07-26)
- 네이버 화면 위에 뜨던 **"지원되지 않는 명령줄 플래그를 사용 중입니다"** 배너는 Edge가
  띄우는 것. `chrome://version` 명령줄 실측 결과 원인 플래그가 **둘**이었다:
  ① 직접 넘기던 `--disable-blink-features=AutomationControlled`
  ② Playwright 기본값 `--no-sandbox`
- ①은 제거(→ `add_init_script`의 `navigator.webdriver` 은닉만으로 동일하게 `undefined`
  유지됨을 실측), ②는 `chromium_sandbox=True`로 해제 → 위험 플래그 0개. 배너 사라짐.
  샌드박스가 막힌 환경을 위해 msedge/기본 × 샌드박스 on/off 4단 폴백을 둠
- 배너 자체가 발행을 막지는 않았다(4편째 실패의 원인은 아래 네비게이션 충돌)

## 로그인·세션 (2026-07-26 실측 재검증)
- **'로그인 상태 유지' 체크박스 id가 `#keep` → `#loginStay`(name `nvlong`)로 바뀌었다.**
  구 셀렉터를 보던 코드가 예외를 통째로 삼켜 매 로그인마다 조용히 실패했고, 그래서
  모든 로그인이 '상태 유지 없음'으로 성립해 **다음 날이면 어김없이 `[EXPIRED]`**가 났다.
  후보 셀렉터를 순회하도록 고쳤고, 실패하면 경고를 띄운다 — 로그인 후 콘솔에
  `'로그인 상태 유지'를 자동 체크했습니다`가 찍히는지 확인할 것
- **로그인 감지는 쿠키 이름이 아니라 값 변화로 판정**한다. 만료된 백업 쿠키에도 `NID_AUT`
  이름은 남아 있어, 존재만 확인하던 구버전은 사용자가 입력하기도 전에 성공 처리하고
  창을 닫아 버렸다(= 로그인하자마자 중단되는 것처럼 보임). 시작 시점 값과 달라지고
  서버측 `verify_login`까지 통과해야 쿠키를 백업한다
- 세션 상태만 빠르게 보려면 `--check-session` (NID_AUT 만료 시각도 함께 출력)
- 정상 로그인 후 콘솔에 `세션 만료 예정: <날짜> (D-N)`이 찍힌다. 실측 2026-07-26 로그인 →
  **2026-08-25 만료**. 이 줄 대신 `[note] 세션 쿠키로 발급됨`이 뜨면 상태 유지가 안 걸린
  것이므로 셀렉터 변경을 다시 의심할 것
- **세션 수명은 약 30일이 상한이고 늘릴 수 없다** (2026-07-26 실측 3종):
  ① 만료는 **발급 시점 기준 고정** — 인증 요청을 보내도 만료일이 밀리지 않음(sliding 아님)
  ② 유효 세션으로 `nidlogin.login`·네이버 메인을 다시 거쳐도 **재발급되지 않음**
  ③ 백업 파일의 `expires`만 길게 조작하는 건 무의미 — 수명은 서버가 판정하므로
     로컬 쿠키만 살아 있으면 그대로 `[EXPIRED]`(이번 사태의 원래 모습)
  → 30일에 한 번은 사람이 자격증명으로 로그인해야 한다. 그래서 **D-7부터 실행 로그에
     만료 임박 경고**를 띄우고, `--force-login`으로 미리 30일을 리셋할 수 있게 했다

## 배치 중단 방지 (2026-07-26)
- 발행 직후 네이버가 `PostList.naver`로 **늦게 리다이렉트**하는데, 그게 다음 글의
  `postwrite` goto와 겹치면 `interrupted by another navigation`으로 죽는다(실측: 4번째
  글에서 발생). `goto_editor()`가 진행 중 네비게이션을 기다린 뒤 최대 3회 재시도한다
- 한 편이 실패해도 남은 글로 넘어간다(실패 글은 미게시로 남아 다음 실행에 재시도됨).
  **연속 2회** 실패면 구조적 문제로 보고 중단

## 동작 특성 (2026-07-22 실측 검증)
- 대상 범위: `BASELINE_FILENAME`(2026-05-14 measuring-ai...) 이후 ~ 최신, 주간다이제스트 제외
- 카테고리는 글쓰기 URL `postwrite?categoryNo=N`으로 사전 선택됨 (발행 팝업에서 이중 확인)
- 본문 크기 15는 붙여넣기 HTML의 인라인 `font-size:15px` → 에디터 `se-fs15` 매핑으로 구현
- **가독성 여백**: 네이버 에디터는 문단 여백이 없어 블록 요소(문단·표·목록·소제목 앞) 사이에
  빈 문단 `<p><br></p>`을 자동 삽입 (소제목 뒤는 본문과 밀착). 2026-07-22 첫 글에서 벽글
  현상 확인 후 추가 — 제거하면 가독성 회귀함
- 서체는 붙여넣기 후 Ctrl+A → 고정 툴바 서체 버튼(`data-group='propertyToolbar'`) → 마루부리 클릭
  (크기는 요소별 보존됨)
- 표·볼드·소제목(fs19)·링크가 에디터 네이티브 컴포넌트로 변환됨
- 태그는 포스트 태그 앞 5개 자동 입력
