# /tidy-claude-md — CLAUDE.md 진단·정리 스킬

CLAUDE.md(또는 AGENTS.md)가 시간이 지나며 비대해지고 규칙이 서로 충돌하는 것을 막는다. 앤트로픽 `claude-md-management` 플러그인의 6지표 채점을 참고하되, **이 저장소의 CLAUDE.md는 길이의 대부분이 실수로 얻은 함정·교훈 기록**이라는 전제 위에서 움직인다. 목표는 삭제가 아니라 정리다.

## 사용법

```
/tidy-claude-md              # 진단 + 정리 계획 제시(승인 후 적용)
/tidy-claude-md --diagnose   # 진단만(등급표 + 이슈 목록). 파일 수정 안 함
/tidy-claude-md --merge      # 이번 세션에서 새로 얻은 교훈을 한 줄로 병합
```

## 절대 원칙 — 교훈은 지우지 않는다

CLAUDE.md의 길이 대부분은 실수로 얻은 함정·주의·워크플로 지식이다. 이것을 "간결성"을 이유로 삭제하면 그 실수를 반복하게 된다.

- **함정·주의·교훈·`실측`·워크플로 지식은 절대 삭제하지 않는다.** 옮기거나 압축은 하되, 내용을 버리지 않는다.
- 정리 = ① 중복 통합 ② 죽은 참조(없어진 파일·플래그·경로) 갱신 ③ 충돌 규칙 해소 ④ 계층 재배치(색인 vs 심화) ⑤ 모호한 규칙 구체화. **삭제가 아니다.**
- 무언가가 실질 지식인지 군더더기인지 애매하면 **남긴다.**
- CLAUDE.md 수정은 폭발 반경이 크다. 승인 전에는 한 글자도 고치지 않는다.

## 6지표 진단 루브릭 (A~C 등급)

플러그인 기준을 이 저장소 맥락에 맞게 변형한다.

| 지표 | 무엇을 보나 | A의 모습 |
|------|-------------|----------|
| Commands | 빌드·서브·테스트·린트 명령이 있고 **실제로 맞는가** | 복붙하면 바로 도는 명령어 |
| Architecture | 디렉터리·레이아웃·데이터 흐름 설명이 실제와 일치 | 신규 합류자가 구조를 그릴 수 있음 |
| Patterns | 컨벤션이 잡혀 있고 서로 모순 없음 | 규칙끼리 충돌 0 |
| Conciseness | 중복 없음, 세부는 알맞은 자리(색인 vs 심화)에 | 같은 말이 두 번 없음 |
| Currency | 죽은 참조(없어진 파일·플래그·날짜) 없음 | 언급된 파일·플래그가 모두 실존 |
| Actionability | 규칙이 구체적·검증 가능, 모호어 없음 | "적절히" 대신 수치·조건 |

## 워크플로

**1단계 — 읽기.** `CLAUDE.md`(있으면 `AGENTS.md`·`~/.claude/CLAUDE.md`도) 전문을 읽는다. 규모가 크면 섹션별로 훑되 전체를 본다.

**2단계 — 진단(수정 없음).** 6지표를 A~C로 채점하고, 근거를 **구체적 위치와 함께** 제시한다:
- **중복**: 같은 지침이 반복된 곳(줄·섹션 대조).
- **죽은 참조**: 언급된 파일·경로·플래그·스크립트가 실존하는지 `ls`·`grep`으로 **직접 확인**한 뒤 죽은 것만 표시. 문서가 틀렸을 수도, 코드가 바뀌었을 수도 있으니 반드시 대조한다(추정 금지).
- **충돌**: 서로 어긋나는 규칙 두 개를 나란히 놓는다.
- **모호**: `적절히`·`많이`·`잘` 같은 검증 불가 표현.
- **비대**: 색인에 있어야 할 한 줄이 심화 설명으로 부풀거나, 심화 내용이 색인에 섞인 곳.

**3단계 — 정리 계획 제시.** 무엇을 통합·이동·갱신·구체화할지 목록으로 낸다. **두 갈래로 나눈다**:
- *기계적(안전)*: 죽은 경로 갱신, 글자 그대로의 중복 제거, 명백한 오타.
- *판단 필요*: 재구조화, 압축, 충돌 해소. 충돌의 정답이 애매하면 **어느 쪽이 맞는지 사용자에게 묻는다** — 임의로 고르지 않는다.

아직 파일을 고치지 않는다. 승인을 기다린다. `--diagnose`면 여기서 멈춘다.

**4단계 — 적용(승인 후).** 외과적으로 고친다. 교훈·함정은 전부 보존한다. 중복은 한 곳으로 합치고, 심화 설명이 색인을 부풀리면 해당 스킬의 커맨드 파일이나 PRD로 옮기고 CLAUDE.md에는 한 줄 포인터만 남긴다(옮긴 내용은 유실 없이 그대로 이동).

**5단계 — 검증.**
- 빌드가 여전히 통과하는지 확인: 이 저장소는 `bundle exec jekyll build`(Ruby 부재 환경이면 `npx -y sass` 컴파일 체크 등 대체 수단). 다른 프로젝트는 해당 빌드.
- `git diff`를 한 줄씩 훑어 **삭제된 것이 중복·서식뿐이고 실질 교훈이 아님**을 확인한다. 실질 내용이 순삭제됐으면 되돌린다. 유용한 대조: 정리 전후 파일에서 `함정`·`실측`·`주의`·`WARN` 등 교훈 표지 개수가 줄지 않았는지 센다.
- 전후 등급을 다시 매겨 보고한다.

**6단계 — 커밋은 따로 묻는다.** 승인 없이 커밋하지 않는다. CLAUDE.md 변경은 폭발 반경이 크므로 **단독 커밋**으로(다른 변경과 섞지 않는다). 푸시는 프로젝트 표준(`git fetch origin && git rebase origin/main --autostash && git push origin main`).

## 세션 교훈 병합 모드 (`--merge`)

작업 세션 끝에 새로 발견한 컨벤션·트러블슈팅 지식을 CLAUDE.md에 **한 줄 교훈**으로 합친다(플러그인의 `/revise-claude-md`에 대응).

- 새 줄은 기존 구조의 알맞은 섹션 안에 넣는다(맨 끝에 쌓지 않는다).
- 이미 있는 내용이면 중복 추가하지 않는다.
- "무엇을 하라"가 아니라 "왜 그런지"가 드러나게 한 문장으로 — 나중의 나와 동료·에이전트가 판단을 되짚을 수 있게.
- 날짜는 절대일자로 적는다(`오늘`·`최근` 금지).

## 안전 점검표 (적용 직전)

1. 삭제하려는 줄이 함정·교훈·워크플로 지식인가 → 그렇다면 삭제 아닌 이동.
2. "죽은 참조"라고 판단한 파일·플래그를 실제로 `ls`·`grep`으로 확인했는가.
3. 충돌 규칙의 승자를 내가 임의로 정하지 않고 물었는가.
4. 빌드가 통과하는가.
5. 커밋을 CLAUDE.md 단독으로 분리했는가.

## 출력

`--diagnose`면 6지표 등급표 + 이슈 목록으로 끝낸다(수정 없음). 전체 정리면 4~6단계를 거쳐 전후 등급과 변경 요약을 한눈에 보고한다.
